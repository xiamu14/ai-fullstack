# 设计稿如何转成开发约束

## 题干

让 Agent 根据设计稿开发页面时，如何减少自由发挥并保持实现可维护？

## 参考答案

1. 设计约定：把颜色字体间距等规则转成明确设计约束；从设计稿识别布局结构与可复用组件。

2. 分层实现：先搭建页面布局骨架再落实细节；将场景渲染与数据面板等不同职责拆开。

3. 交付核对：交付可修改的代码而非只有静态图片；对照设计检查布局并验证交互与窄屏表现。

给 UI 设计师整理了一套 VibeCoding 实战流程。
这次不是做普通后台页面，而是用一个「3D 数字孪生大屏」案例，完整走一遍：

从 Figma 设计稿 到 Codex 开发落地 再到可运行的线上页面。

整个流程拆成了 5 步：

01. 先定义 Codex 的开发角色 不要一上来就让 AI 写代码。 先通过 AGENTS.md / System Prompt 明确它的身份： 它不是自由发挥的视觉设计师，而是严格按照规则执行的前端工程师。

02. 定义 Design Token 在页面开发前，先把颜色、字体、间距、圆角、阴影、图表和动效规则写清楚。 Design Token 是设计师控制 AI 输出的核心。

03. 先搭 DashboardLayout 骨架 通过 Figma MCP 读取页面结构，先完成大屏布局： 3D 底层、顶部导航、右侧面板、地图浮层和工具按钮。 先让页面“站起来”，再让它“变漂亮”。

04. 3D 场景独立成 Scene3D.jsx C4D 负责整理资产，导出 Web 可加载的 GLB。 Codex 负责用 Three.js / R3F 加载模型。 Scene3D 只管理空间逻辑，UI 面板和图表继续留在上层。

05. 数据面板独立成 PanelContent.jsx 右侧数据面板信息密度最高，不能都堆进 DashboardLayout。 指标、图表、酒店入住率、道路速度、事件列表都要拆成独立模块。

这套流程最重要的不是“让 AI 自由发挥”，而是：

先定义规则， 再搭建结构， 最后让 Codex 在清晰边界里高效执行。

对 UI 设计师来说，VibeCoding 的核心能力不是写所有代码，而是把你的设计判断转译成 AI 能执行的规则系统。
Token 定规则，Figma 给结构，Codex 做落地。

以前看到喜欢的网页，最多只能默默收藏。

因为想做出类似的效果，得先研究页面布局、配色、组件，再从头写代码。对于不会前端的人来说，基本看到第一步就放弃了。

探果里的「图像转代码 Skill」，它做的事情很直接：
上传一张网页截图或设计稿，让AI分析页面，再生成对应的前端代码。

我这次找了一张网页作为参考图，交给AI后，它会自动拆解：
✅ 页面由哪些模块组成
✅ 标题、卡片和按钮怎么排列
✅ 使用了什么配色和间距
✅ 哪些部分可以抽象成组件

分析完成后，再生成 React JSX 或者 HTML/CSS 代码。
最后做出来的页面，虽然不能说和原图像素级一致，但整体布局、三栏卡片、渐变背景和按钮位置都还原出来了。

最重要的是，得到的不是一张静态图片，而是可以继续修改的网页。

生成后还可以接着告诉AI：
“把背景颜色换成紫色。”
“把文案改成我的产品介绍。”
“调整一下卡片间距。”
“增加手机端适配。”
它会在现有结果上继续修改。

这个Skill最吸引我的地方，不是帮专业前端一键完成所有工作，而是让完全不会写代码的人，也能快速把一个想法变成看得见的网页雏形。

以前是：
看到喜欢的网页 → 收藏 → 没有然后
现在是：
上传参考图 → 说清需求 → 获得可以继续修改的网页

如果你刚开始接触AI Skill，又想快速体验到“AI真的在替我完成工作”，这个很适合作为第一个尝试。
