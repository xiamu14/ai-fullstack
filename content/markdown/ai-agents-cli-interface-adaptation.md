## 题干

将多个 Agent CLI 接入统一桌面界面时，直接嵌终端和解析成原生组件各有什么取舍？

## 参考答案

1. 接入方式：嵌入终端可复用 CLI 已有交互能力；原生展示需要解析事件并映射到界面状态。

2. 兼容风险：解析层应考虑不同 CLI 的格式和版本变化；避免适配代码破坏原有审批及工具执行语义。

3. 用户验证：保留会话与文件差异等任务关联信息；检查显示完整性及内存响应等实际使用成本。

ADE(Agentic Development Environment)，相对于vscode/zed之类的IDE，ADE的特点是左栏 - 会话索引，主界面 - 主会话区，右栏 - Diff/文件/终端等，保证用户注意力集中在与Agent的交互上。

常见的ADE，如ChatGPT/Claude Desktop/Cursor/ZCode/Workbuddy，已经做的非常好了。但是一些人会用Grok/Pi，或者既想用到官方CLI的能力，又想拥有GUI界面的良好体验，亦或是想要统一管理，避免同时开N个App的内存/心智占用，那么就需要一个第三方的ADE，来解决这些问题。

主推是两个开源项目，Synara、Orca。
Synara，仿照Cursor界面，具备看板/PR/自动化等功能，支持分屏/侧边聊天/浏览器/AppSnap/Handoff，适配Codex/Claude/Cursor/Gemini/Grok/Droid/Kilo/OpenCode/Pi，最大优点是界面非常优雅，缺点是作为开源项目起步不久，在思考过程、图表可视化等方面会有一些小bug

Orca，相比Synara，最大区别是主界面是终端形式，虽然不够美观，但减少了适配显示功能的摩擦，使用体验较好。它还具备手机端远程连接、内存管理、Computer Use，甚至还有个手机模拟器，主打一个功能全面。

另外一些是Superset(开源)、Conductor、SuperConductor，这些App其实与以上的大同小异，而在使用时对我最大的困扰就是，它们都会用agent的hook甚至装MCP，在使用体验上会有一点小小的摩擦。而Synara和Orca可以很干净的使用，同时作为开源项目，也可以自己修改甚至加功能提PR上去，很好。
