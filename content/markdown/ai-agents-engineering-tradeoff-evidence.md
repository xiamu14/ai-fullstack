## 题干

面试中介绍一个 Agent 项目，怎样证明自己做过选型和故障改进，而不只是拼过 API？

## 参考答案

1. 问题约束：先说明业务目标与质量延迟成本等限制；明确自己实现的能力及负责范围。

2. 比较依据：列出实际比较过的方案及未选择的原因；用可复查的评测或运行数据支持选型。

3. 改进闭环：展示一个失败定位修复与复测的完整案例；说明上线表现或新条件下结论的适用边界。

最近面了不少大模型应用开发的候选人，有个感受越来越强烈：大部分人被刷，不是因为项目经验不够，而是讲项目的方式完全跑偏了。简历上堆着RAG知识库、智能Agent、自动化工作流，工具链列一长串，整体流程也能说出个大概。但只要顺着细节往下追两三层，真实水平就藏不住了。

面试官到底在听什么？很多求职者以为我们在数他调了多少API、用了多少框架，完全不是。真正盯的就三件事：第一，你能不能把一个真实的工程落地难题从头到尾讲明白；第二，日常开发中有没有架构选型的思考习惯，而不是照着教程堆功能；第三，遇到线上故障能不能自己排查、自己兜住，别两手一摊等别人救。这三点，才真正决定你能不能拿offer。

大模型应用开发项目的正确讲法，分三步走。

第一步，先把项目拆清层级。所有LLM应用项目的讲述，本质就三层。功能层：你实现了什么能力，RAG问答还是Agent调度，链路跑通了没。设计层：架构为什么这么定，切片策略和Embedding怎么选的，评估指标怎么建，这些决策背后有没有你的逻辑。工程层：推理延迟怎么压、幻觉怎么兜底、上线后效果衰减怎么监控、Token成本跟质量怎么平衡。可惜多数人只停在第一层，面试官追问一句“还考虑过哪些方案，为什么没选”，直接卡住，这时候面试基本就判了上限。

第二步，每个技术点都按“讲法结构”提前准备。拿模型选型举例，浮在表面的讲法是“我用GPT-4，效果还行”，信息量约等于零。面试官更想听的是：业务场景对延迟和效果的具体约束是什么；不同模型在推理速度、成本、中文表现上你怎么做的横向对比；评测集怎么构造，badcase怎么归类；上线后实际效果跟预期差多少，怎么迭代的。把这一串讲清楚，面试官不用多问就能判断你的level。

第三步，会做技术对比的人天然占优势。很多候选人选型就是一句“这个模型主流、用的人多”，在面试官听来等于没给信息。我们想听的是你怎么比较、怎么取舍：GPT-4和Claude在延迟、成本、中文场景到底差多少；为什么这个场景RAG够用而不是上微调；换个高并发的场景，选型结论会不会变。能把决策逻辑讲清楚，才说明你真想过，不是照着教程复制了一遍。

总结一句：面试官不怕你项目小，怕的是你做过却没思考过。把“为什么这么选、还试过什么、踩过什么坑、怎么验证改好了”这条完整链条讲出来，比简历上堆十个模型名都管用。

我做AI应用开发这段时间，踩过最多的坑不是模型不懂，而是“以为懂了”和“真能跑起来”之间隔着一整条工程链。回头看，真正让我从“概念党”变成“落地派”的，是这几件事。

1. 看技术文档不是翻书，是做“翻译”
别一上来就看二手教程。选个开源框架或大模型API，直接啃官方文档。遇到RAG链路，用大白话给非技术同事讲一遍；遇到Temperature、Top-p这类参数，亲手调几组值看输出变化，画张“参数-效果”对照表；遇到接口延迟和Token消耗，自己压测一遍再对比官方SLA。翻译明白了，才算真懂。

2. 复刻开源项目，不是抄袭，是练手感
最容易犯的错是看完别人项目演示觉得“原理我都懂”，换批数据就不知道怎么调了。去GitHub找热度高的AI应用，知识库问答、Agent工具调用都行，照着源码自己复刻——搭向量库、写Prompt链、对接流式输出。跑通后对比原版，差距全在异常处理、边界情况和响应速度的折中设计上。

3. 每天磨一个场景，练工程手感
AI应用开发能力是“用”会的。每天30到40分钟，专练一个场景：今天做文档问答的分块策略和检索调优，明天做工具调用的Schema设计和异常兜底，后天做流式输出的断连处理。把大模型能力拆成可测试的小任务，反复调参数和Prompt，记录效果变化。这种手感，看再多文章也换不来。

4. 案例库就是你的弹药库
排查问题慢，不是技术差，是参考案例少。刷GitHub Trending、Hugging Face论坛、机器之心时，看到好的架构设计、失败复盘、优化策略，随手截图按场景分类存好。遇到线上问题没思路？翻案例库找对照。时间长了，定位问题的速度能快一倍。

现在很多人的 AI 学习路线是：Prompt → RAG → Agent，先拼出一个 Demo 再说。
我反而建议先刹车。真做项目时，更容易把人卡住的是：数据不会处理，模型为什么出错说不清，本地能跑，却上不了线。
AI Engineer 不是“会用 ChatGPT 的程序员”。你要能把数据、模型、应用和部署串成一条真正能运行的链路。

所以我更认可这个顺序：
🐍 先用 Python 拿到“干活能力”
变量、循环、函数、OOP、异常和文件处理是底座；NumPy 处理数值与数组，Pandas 清理脏数据，Matplotlib 把数据画出来。学完就做小项目，计算器、问答游戏都可以。重点不是项目有多酷，而是你能不能自己写、自己查错。

🧠 再补数学、ML 和 DL
数学不用学成数学系，但要能理解模型怎么从数据里找规律、做预测、再根据错误调整。接着进入监督/无监督学习、分类、回归、特征工程，然后再学神经网络、前向/反向传播和损失函数。
这部分看起来没 Agent 性感，却决定了模型出 badcase 时，你是只会换个 Prompt，还是真能找到问题。

🤖 然后才是 LLM 和 Agent
先搞懂 NLP、Vector、Embedding 和向量数据库，再学 RAG：模型不知道你公司的私有数据，怎么让它基于这些数据给出回答？
再往后才是 Agent。普通 GenAI 可以帮你查航班；Agent 要做的是把查航班、做行程、订酒店连成一段 Workflow。一个 Agent 真正跑起来，至少要组合 LLM、Memory 和 Tools，这时再看 LangChain、LangGraph 才有上下文。

🚀 本地跑通还不算完 你得让别人真的用上它。Git/GitHub、Docker、云服务、MLflow、Apache Airflow，这些才会把一个本地模型变成可管理、可部署的系统。

整条路线至少可以按3个月、每天 2–4 小时的投入做预期。别只收藏课程，每学一层就做一个可展示的东西，放到 GitHub 或 LinkedIn 上。
