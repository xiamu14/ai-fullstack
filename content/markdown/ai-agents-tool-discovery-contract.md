# 工具发现与执行如何分离

ID: tool-discovery-contract
Library: ai-agents

## 题干

一个工具网关提供 discover、inspect、run 三步接口，它们各自应该解决什么问题？

## 参考答案

1. 发现候选：discover 根据任务寻找候选工具；候选信息应包含能力及可用性等选择依据。

2. 检查契约：inspect 获取目标工具的参数结构和约束；执行前确认价格或权限等使用条件。

3. 执行追踪：run 按已确认的契约执行工具；保留调用标识及原始执行结果供追踪核对。

Monid 开源了——OpenRouter 让你一个 key 调所有模型，它想对 agent 的工具做同一件事：一个 base URL、一个 key，接上 72 家供应商的 2000 多个工具。联网搜索和抓取、人物与公司信息补全、社交平台、点评和市场数据，还有视频、图片、语音生成。

🤖 README 里有句话是写给 agent 看的：「你是 AI agent 吗？把 monid.ai/SKILL.md 抓下来存进 skill 目录，剩下的它自己会办。」

🔍 三个动词，前两个免费：discover 找接口、inspect 看输入格式和价格，都不收钱；只有真正执行的 run 按用量计费。

📊 discover 是按「这活是干什么的」去排，不是按厂商名去查。它一次横扫整个目录，每个候选都带着价格、实时健康度、实测 p50/p95 延迟，还会提示有没有更便宜或更合适的接口。换句话说，接口是调用那一刻选的，不是几个月前写死在代码里的那家。

💰 计费这块挺实在：每个连接器自己声明按次、按返回条数还是按单位量（每千字符、每秒视频）。厂商报错、公司没匹配到、人没解析出来——这些都算「完成了，但收 0 元」。结算发生在原始响应上、在任何输出映射之前，线上回来什么就按什么算。

🧩 注意开源的是哪部分：这个仓库放的是连接器层，也就是描述每个接口的那套通用框架，不是整个平台。因为写法是声明式的，接入这件事 coding agent 就能干——把 API 文档和这个仓库丢给它，「把我的 API 接进 Monid」就变成一个 PR。仓库里还配了 AGENT.md 当任务说明。

工程上挺规矩：Deno 2.x，188 个回放测试全程零网络，CI 不需要任何厂商密钥。

agent 生态这两年一层层在长「路由器」：模型有 OpenRouter，harness 有 HarnessRouter，会话历史有 Wake 和 AgentsView，现在轮到工具调用这层了。
