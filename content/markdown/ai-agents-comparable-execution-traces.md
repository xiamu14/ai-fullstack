# 两条执行轨迹如何公平比较

## 题干

两个 Agent Session 的 Token 和耗时相差很大，怎样先确认可比，再找到真正分歧？

## 参考答案

1. 可比条件：核对任务模型运行框架与环境是否发生变化；说明无法控制的差异避免错误归因。

2. 结果过程：分别比较任务结果证据与执行步骤；统计时间用量失败重试和上下文组成的差异。

3. 分歧定位：定位轨迹首次重要分歧及其后续影响；用证据提出优化方向而非只按总 Token 排名。

这次主要把 Trace Compare 重新整理了一遍。
以前对比两个 Session，更多还是“把两条轨迹放在一起看”，信息很多，但结论要自己找。
这版重点补了几个真正有用的东西：
先判断能不能比：Task、Model、Harness、Environment 有没有变化，避免拿两条完全不同的任务硬对比。
核心差异直接算出来：时间、Token、失败调用、重试、证据覆盖，一眼就能看 A/B 差多少。
结果和过程分开看：不仅看“做没做完”，还会看测试、构建、Artifact 这些证据。
上下文效率：能看到 Skills、Tool I/O、Memory 等到底占了多少上下文，有没有明显浪费。
关键分歧点：直接定位两条 Session 从哪一步开始走得不一样，不用自己盯着两条长 Trace 找。
差异归因 + 优化建议：尽量解释 Token、时间为什么变多，以及下一步更值得优化哪里。
现在我希望这个功能解决的不是：
“两个 Session 有什么数据？”
而是：
“它们到底哪里不同，为什么不同，我下一步该改什么？”
