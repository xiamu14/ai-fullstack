# Agent 发现缺少关键需求时，如何把澄清接入执行流程？

ID: clarification-node
Library: ai-agents
Version: 2026-10-24.1

## 题干

Agent 发现缺少关键需求时，如何把澄清接入执行流程？

## 参考答案

澄清是暂停并补充原任务上下文的执行节点。

缺口判断：识别影响执行的缺失信息；提出具体问题；选项之外允许自由补充。

暂停绑定：保存原任务上下文和 checkpoint；关联会话执行和请求标识；等待回答期间不猜测执行。

回答恢复：检查回答格式与请求状态；一次请求只接受有效提交；把回答写回原上下文再继续。

答案与细则由整理者依据正文补充；已核对正文证据，不代表原作者标准答案。

在CC 中，这项工具名为 AskUserQuestion。它允许 Agent 提出问题，并提供单选、多选或自由补充入口；用户回答后，结果会写回当前任务上下文，Agent 再继续规划或执行。
	
因此，AskUser 不只是一个问答组件，而是一套发现信息缺口—暂停任务—获得回答—继续执行的交互机制。界面上的候选项只是呈现方式，不应被当成能力本身。
	
1️⃣CC：AskUserQuestion
1. Agent 判断自己缺少信息；
2. 调用 AskUserQuestion，输出一组结构化问题；
3. 前端渲染成单选、多选或文本输入；
4. 用户作答后，答案被回传给 Agent；
5. Agent 带着补充后的上下文继续执行。
工具调用 + 权限拦截 + UI 渲染的人机协作节点。每个问题通常包含问题正文、短标签、选项、是否多选、是否允许自由输入等字段。
	
2️⃣Cursor：ACP结构化提问
Cursor 的 Ask 不是工具，而是一个 交互模式。
Ask 模式通常是只读的：它会读取你提供的代码或上下文来回答问题，但不会像 Agent 模式那样自动改文件、跑命令、执行多步操作。
	
3️⃣Gemini CLI：Ask User tool
它常见于 Gemini CLI 的计划模式或复杂任务流程中。比如 Agent 正在分析代码库、规划改动，但发现目标不够明确，就会通过 ask_user 暂停，向用户提出更具体的问题，收集偏好或确认目标后再继续。支持把问题组织成结构化列表，通常包括单选、多选或文本输入等形式。
	
[立马暴富]执行流程
用户提交选项时，客户端会把答案和 request ID 一起发回服务端。服务端检查答案格式、请求是否仍在等待、是否超时，以及提交者是否有权限。校验通过后，这次提问会被标记为已回答，避免重复提交。
	
系统根据 request ID 找到对应的 run ID，再根据 thread ID 找回原会话和保存的 checkpoint。用户答案被写入原任务上下文，成为 Agent 下一步推理可以读取的新信息。三个 ID 的作用很简单：thread ID 找会话，run ID 找本次执行，request ID 找这次提问。
