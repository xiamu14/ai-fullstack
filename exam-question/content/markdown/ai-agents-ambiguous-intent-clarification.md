## 题干

## 参考答案

1. 歧义保留：结合当前任务与已知行为列出合理候选意图；不把含糊情绪表达直接等同于某个高风险操作。

[用 Ling-3.1-flash 和 Jev 做个办公智能体](https://www.xiaohongshu.com/explore/6ad19ea2000000001a026b8b)，古希腊掌管代码的神，2026-10-16T09:11:48.000Z，仅正文。

📌 最近办公成了 LLM 落地的最卷赛道，但是我发现办公 Agent 最常见的翻车，不是做得不好，而是没问清楚就开干。

📌 用户给出指令“帮我写周报”，Agent 马上交出一份结构完整、语气专业的周报，里面的“已完成事项”全是幻觉。目标没定、材料没给，它已经在生成交付物了。

📌 所以最近搭建了一个带意图澄清的办公 Agent，把“当前信息够不够做下一步”拆成一个独立的系统决策：
🌟 Ling-3.1-flash 负责生成：组织内容、向用户提问、规划工具调用。
🌟 System 1 Model Jev 负责判断：这一步需要的信息是否充足，返回结构化判断结果。
每一步执行动作前 Jev 从目标、输入、交付物、硬约束、动作范围、需求冲突六个维度分别判断，Ling-3.1-flash 负责长程任务执行。为什么选择 Ling-3.1-flash？因为 Jev 判定的集成导致系统调用链路变长，生成模型必须够快、够省，长链路还要稳。Ling-3.1-flash 是 560B-A25B 的 MoE 模型，正好对上这个需求。

📌 我实际测试了一个真实的办公场景：依据我维护半年多、分支杂乱的代码仓库，做一份开发历史、功能总结的 PPT。我只给了一句话，Ling-3.1-flash 询问了必要的背景信息，我补充完它才开始读材料、出大纲、生成，执行中关于需要涵盖的分支这些关键决策会提前问我，以免意图不清导致返工。最终在多轮打磨下做的 PPT 布局清晰，并且提交内容、甚至 LLMForge 的功能截图都是准确的。

🤔体验完这套 Ling-3.1-flash + Jev 做完最大的感受：衡量目标应该是端到端的任务成功率，而不是单次生成的成功率，有时候除了卷 Coding 榜单，意图澄清这些提升用户体验的路径也是值得关注的。
