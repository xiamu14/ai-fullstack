## 题干

Planner 把需求转成 DAG 任务图后，执行前和执行中分别要检查什么？

## 参考答案

1. 图结构：检查节点引用有效且没有依赖环；检查必要节点连通及输入输出依赖完整。

2. 能力匹配：确认每个节点对应的工具或执行者具备所需能力；明确每个节点的产物与验收条件。

3. 依赖推进：只有上游经过验收后才释放依赖它的下游；节点异常交回协调者处理并受整体预算约束。

## 来源

[Beyond ReAct · 复杂工具的全局规划能力](https://www.xiaohongshu.com/explore/6a10f59c00000000350226c7)，啃代码的小栩，2026-05-23T00:32:28.000Z，仅正文。

Beyond ReAct 讨论的核心问题，不是模型会不会调用工具，而是复杂工具增强任务里，系统是否具备全局规划能力。
过去很多工具型 agent 沿用的都是 ReAct 范式：一边推理，一边调用工具，一步一步往前走。这个方法在简单任务里通常够用，但任务一旦变复杂，就容易陷入局部最优。单步决策看起来合理，整体执行路径却未必合理。
这篇论文提出的关键思路，是把“规划”从执行过程中独立出来。作者提出了一个 planner-centric 框架：先由 Planner 把自然语言 query 转成带依赖关系的 DAG 任务图，再交给 executor 按图执行。重点不再只是“下一步调哪个工具”，而是“整道任务需要哪些工具、它们之间如何组织”。
更重要的是，这项工作并不只是提出一个框架概念，而是围绕“任务图生成”补齐了数据、训练和评测。论文构建了 ComplexTool-Plan 数据集，并采用 SFT + GRPO 两阶段训练 Planner，同时设计了分层奖励函数，用来区分语法错误、环结构、断连图和依赖边质量等不同类型的问题。
实验结果说明，规划质量的提升不仅体现在图结构指标上，也能传导到端到端任务成功率上，同时还能减少 inference steps。换句话说，全局规划带来的收益不只是结构更完整，而是任务完成效果更好，决策效率也更高。
这篇论文更有启发的一点在于，它把 agent 的高层认知结构显式化了。复杂 agent 做不好的原因，未必首先是模型能力不足，也可能是系统从一开始就没有把“规划”作为一个独立对象来建模和优化。

① 研究现状：当前主流 Agent 聚焦单一 Harness 的极致优化，如 Claude Code、Codex 等代表 Agent。单一 Harness 难以兼顾全部领域，某一领域的强化可能削弱其他领域的适配性。现实任务常横跨调研、编程、设计和持续运行，需要组合领域专家。

② 核心挑战：第一，如何自动开发和改进适配单一领域的 Harness？工具、上下文与执行策略的组合复杂，人工试错难以规模化。 第二，跨领域 Harness 如何组织协作？需要匹配任务与专家，安排依赖、产物交接与协同执行。

③ 核心创新点：回应挑战一，Raven 提出 Harness 自进化：根据失败轨迹对 Harness 进行基因重组和编辑，经评测筛选持续改进。 回应挑战二，Raven 通过跨域多智能体协作，由 Host 组织领域专家，用任务图协调依赖和交付。

④ 解决方法：Harness 内部有上下文管理、任务指引、工具选择、行动检查四个策略模块。自进化修改这些策略，模型权重固定。候选通过筛选后再测留出任务。 跨域协作采用主从式编排：Host 从交付物倒推任务图，安排专家、依赖与产物交接，以显式流程降低自主协商的不确定性。启动前检查图结构与能力，验证节点已完成给定任务后释放下游，异常交回 Host，执行受预算约束。

⑤ 实验结果：
验证领域改进：冻结 Qwen3.6-27B，演化后 AppWorld Pass@1 从 41.3% 升至 56.7%。
验证跨领域编排：MAOB 评测领域专家选择与任务依赖。DeepSeek-V4-Flash-0731 下，Raven 的领域级完整规划图匹配率为 86.7%，Claude Code 为 76.2%，Hermes 为 74.8%。
