## 题干

准备在产品中采用尚处试验阶段的页面过渡能力，怎样评估可用性而不影响基本操作？

## 参考答案

1. 版本边界：核对目标框架版本和接口稳定性；不能把试验阶段能力直接假定为稳定 API。

2. 运行范围：验证目标浏览器是否支持所需能力；动画不可用时基本内容与操作仍应可达。

3. 体验验证：响应用户减少动态效果的偏好；检查状态更新及导航在有无动画时都正确。

[React 新动画能力 ViewTransition：页面...](https://www.xiaohongshu.com/explore/6a54f275000000002100824a)，程序员英语buff，2026-07-13T14:13:09.000Z，仅正文。

React 的 ViewTransition 想解决一个很常见的问题：页面切换、元素进入离开、卡片进详情页这些动画，以前经常要自己写很多 CSS 和 JS。现在 React 正在把这件事放进组件更新流程里，让动画更贴近状态变化本身。

🎯 核心设计原则
让 React 负责协调 UI 更新，让浏览器负责捕获快照和执行过渡动画。

⚡ 1. 它解决什么问题？
- 页面切换动画难维护。
- 列表到详情页过渡不连贯。
- enter / exit 动画容易散落在多个地方。
- 手写 DOM 测量和动画代码容易变复杂。

🧩 2. 它怎么工作的？
- 用 `<ViewTransition>` 包住需要动画的组件树。
- 状态变化时，浏览器捕获更新前后的视觉快照。
- React 协调渲染和提交时机。
- 浏览器在旧 UI 和新 UI 之间执行动画。

🚀 3. 适合什么场景？
- 路由切换动画。
- 弹层进入和离开。
- 卡片列表进入详情页。
- 列表重排动画。
- Suspense 内容切换。

🛠️ 4. 工程里怎么用？
- 注意：目前它还是 React Canary 能力。
- 不要直接当成稳定生产 API。
- 动画要适配 `prefers-reduced-motion`。
- 复杂动画可以结合 View Transition Classes。
- 不支持的浏览器要准备降级方案。
