# 短期与长期记忆如何划分

ID: memory-lifetimes
Library: ai-agents
Version: 2026-10-24.1

模块：上下文记忆 · 难度：L1

## 题干

请说明会话内记忆与跨会话记忆的区别，以及为什么不能只按存储介质给记忆分类。

## 参考答案

1. 生命周期：会话内记忆服务于当前交互或任务；跨会话记忆用于后续会话继续使用的信息。

2. 载体区分：同一种存储技术可以承载不同生命周期的数据；保存在数据库里并不自动表示内容值得长期召回。

3. 使用规则：依据任务需要筛选当前上下文的信息；为长期内容设定来源更新与遗忘规则。

其实 Memory 的关注度一直都比较高，只是之前一直没有找到特别有感知的利用场景。大家大致会将记忆划分为短期记忆、长期记忆等等，各种概念的划分五花八门。

简单回顾一下，一般来说：1）**短期记忆**指代当前上下文中的记忆，也就是同一个 Session；2）**长期记忆**指代跨 Session 的记忆。这里的长期记忆，早期主要是为了让 LLM 记住一些用户的基本信息，比如姓名、爱好等等。（注：这里对于短期记忆和长期记忆的解释与 LangChain 的定义不一样，注意辨析。）

[滴滴面试官：你说收悉Agent记忆机制？](https://www.xiaohongshu.com/explore/69ff5d620000000036033909)，算法狗，2026-05-10T01:50:03.000Z，仅正文。

滴滴面试官问：向量库召回不到隐藏因果怎么补？长短期记忆怎么拆？朋友当场沉默。

他面的是网约车策略开发岗，简历写着“熟悉Agent记忆机制”。面试官追问：客服场景里，用户隔几天回头投诉同一笔订单，Agent怎么记住细节？全塞进prompt会怎样？

朋友答：用向量数据库RAG。面试官立刻反驳：用户投诉绕路，三天后随口提了句当时下大雨。向量检索没把“下雨”和“绕路”关联上，漏了关键因果。你怎么补？短期记忆和长期记忆要不要分层设计？哪些该记、哪些该主动忘？

朋友做的项目只是调了LangChain的ConversationSummaryMemory，根本没想过这些问题。

很多人以为Agent记忆就是把历史对话塞进上下文。但上下文一长，关键信息会被淹没，模型还会出现“注意力漂移”。短期记忆的核心不是“存什么”，而是“怎么选”。用滑动窗口加摘要确实常见，但摘要一旦漏了细节，后续全偏。

长期记忆更复杂。向量数据库RAG容易产生语义漂移，相近但不相关的文本会被错误召回，也缺乏因果结构。知识图谱能补这个短板，但维护成本极高。

成熟系统走分层混合路线：即时层用上下文窗口，会话层用滑动窗口加摘要，持久层用向量数据库，结构层可选知识图谱。

还有一个被忽视的问题：Agent该遗忘什么？只有写入没有清理，长期运行后效率下降、噪声堆积。忘记什么，比记住什么更需要设计。

技术选型可以迭代，但如果连“记什么、忘什么”都没想清楚，再精致的记忆系统也只是个更复杂的失忆工具。
