# 什么时候直接搜索原文

## 题干

知识材料已保存在本地文件里。什么时候可以直接搜索原文，什么时候更适合引入向量检索？

## 参考答案

1. 直接搜索：已知关键词或精确标识时可直接搜索原文；材料规模和扫描成本可控时可避免额外索引维护。

2. 语义检索：问题与原文用词差异大时向量检索有价值；检索方案要考虑材料规模和更新频率。

3. 方案比较：用真实问题集比较召回效果和回答证据；同时比较查询延迟与索引维护成本。

✏️ Beyond Semantic Similarity: Rethinking Retrieval for Agentic Search via Direct Corpus Interaction

🧐 论文的反直觉答案：与其把 retriever 优化得更好，不如把它整个扔掉——让 agent 像软件工程师调试代码那样，对 raw corpus 直接用 grep / find / shell 翻。把 retrieval 从"模型问题"重新框成"接口设计问题"。

🚀 三件套方法：
▸ 双结构同源对照：DCI-Agent-Lite（GPT-5.4 nano + 仅 bash + read，验证接口本身效果）vs DCI-Agent-CC（Claude Sonnet 4.6 + Claude Code 全家桶，测性能上限）。两者都禁用任何检索、重排、索引，凡有提升都能干净归因到"DCI 接口"。

▸ Runtime Context-Management 五档（L0→L4）：grep 输出会塞爆 context，论文用 截断 + 压缩 + 总结 三套机制组合；关键发现 L3 最优，越激进反而越差（见 p9 Table 6）。

▸ Coverage + Localization 两个新指标：trajectory-level 度量"是否触及 gold doc"和"触及之后能否聚焦小 evidence span"，解释了为什么 DCI 覆盖率 28.0 反而比覆盖率 56.7 的基线高 28 点。

🔥 工程含义：当模型够强，更高分辨率的接口比更好的 retriever 更值钱——内部知识库 / 代码 repo / 法律医疗文档这种动态中小 corpus 直接交给 CLI agent grep。
