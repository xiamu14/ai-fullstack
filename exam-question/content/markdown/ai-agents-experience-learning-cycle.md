## 题干

Agent 把失败写进文件后仍反复犯同样的错，经验沉淀还缺哪些环节？

## 参考答案

1. 经验来源：记录具体失败及发生时的条件；保留能核对原因的执行证据。

2. 持久组织：把确认有价值的经验写入可检索的持久载体；记录适用范围避免把偶然现象变成通用规则。

3. 后续使用：下一次相关任务开始前能召回并读取经验；用回归任务验证经验是否减少同类失败。

前段时间听李继刚和孟岩的播客很有启发。基于奥卡姆剃刀原则，我给本地 Hermes Agent 做了一个很小的进化 Skill。
我认为，一个本地 Agent 真正想进化，最小必要条件只有三件事：
1. 能看到自己过去犯过什么错
2. 能把学到的东西写入一个持久化的地方
3. 能在下一次任务里重新读到这些经验

其他的都是在这三件事的基础上的优化。

这个项目不是微调，不是训练，也不是云端记忆。
更像一个本地的“经验账本”。

很多 Agent 项目看起来能对话、能调工具，但真正进入工程场景后，问题才刚刚开始：
上下文如何持续组织？ 工具调用如何被约束和审计？ Trace 如何回放？ Eval 如何成为回归基线？ Memory / Skills 如何沉淀为长期能力？ 本地执行如何建立安全边界？ Agent 如何从失败中持续进化？

所以我开源了 Evolva —— 一个面向真实工程场景的 Local-first Self-Evolving Agent Harness。
它不是聊天机器人，而是一套 Agent 运行控制平面：
Tool Calling｜Long-term Memory｜Skills｜MCP｜Workflow｜Trace / Replay｜Eval Harness｜Guardrails｜Sandbox｜Multi-Agent｜Self-Evolution｜CLI / TUI

Evolva 的核心不是“让 Agent 回答一次问题”，而是让 Agent 的每一次执行都可以被：
观察、追踪、评测、复盘、沉淀、再进化。
它围绕一条完整闭环设计：
Plan → Act → Observe → Evaluate → Evolve
每次运行都会留下 Trace，每个失败都可以进入 Eval，每条经验都可以沉淀为 Memory 或 Skill，最终反哺下一次执行。

如果你正在研究 Agent Harness / MCP / Eval / Workflow / Self-Evolution，Evolva 不是一个 chatbot demo，而是一套面向真实工程场景落地的 Agent Infra 基础设施。
