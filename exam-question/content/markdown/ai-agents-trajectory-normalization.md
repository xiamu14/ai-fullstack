# 轨迹摘要与回放如何分工

ID: trajectory-normalization
Library: ai-agents
Version: 2026-10-24.1

模块：工程质量 · 难度：L3

## 题干

不同 Agent 的原始轨迹格式各异，如何统一分析，又不破坏回放与审计能力？

## 参考答案

1. 统一表示：把不同来源的动作和结果映射为统一事件结构；保留事件顺序及父子或调用关联标识。

2. 用途区分：摘要或归一化数据用于搜索分析；精确回放需要原始事件而非仅凭摘要重建。

3. 原始保全：保存原始轨迹并建立到统一事件的引用；记录转换版本使分析结果可追溯。

agent 今天不太会从过去经验里变好，而经验又拆在 Claude Code、Codex、Letta Code 等不同 harness 里。

人会换工具，团队偏好也不同。要跨工具学习，先得有标准的「经验数据」格式。

学习主要发生在 token 空间，是 agent 自己消化经验，去改 system prompt、skills，甚至改 harness。理想格式两条：跨 harness 统一，减少格式噪音；token 要省，好让 agent 读得完。

Letta 他们推出 trajectory 包，把各 harness 轨迹收成一致、对 agent 友好的记录，服务读过去会话、形成记忆，并砍 metadata 开销。对照 Harbor ATIF：ATIF 做高保真回放与基准，保留逐步 token、完整 tool payload、不截断输出；消费者是 agent 时，只留理解这局发生了什么的最少细节。

一条 trajectory 是有序 records：meta 标明 harness，再是 user、可选 reasoning、带 tool_calls 的 assistant、用 tool_call_id 挂上的 tool 结果。契约见 trajectory-v1.schema.json。

丢掉信封、重复字段、UI 事件流、加密 reasoning blob，长 tool 结果可截断。

Anthropic 计 token 的真实 coding session 抽样：相对原生，Claude Code 默认约 5.6 倍、Codex 约 5.4 倍；ATIF 压得少得多。

用法：listTrajectories 发现本机会话，normalizeTranscript 归一；文中循环 claude-code、codex、letta-code 做索引或喂 memory agent。

Letta Code 用它读别家会话做记忆 bootstrap，后台 dreaming 可扫整机多 harness。
