# 安装 Skill 后应检查什么

ID: skill-usage-audit
Library: ai-agents
Version: 2026-10-24.1

模块：工程质量 · 难度：L2

## 题干

某 Skill 已安装但任务效果没改善，如何区分未读取、未遵循和没有收益？

## 参考答案

1. 可用与读取：检查 Skill 能否被发现并提供给任务；通过执行轨迹确认它是否被实际读取或调用。

2. 遵循程度：核对关键步骤和参考资产是否真正被使用；区分合理调整与遗漏必要流程。

3. 实际收益：对照基线检查最终交付质量；同时比较步骤成本与延迟避免把调用本身当作增益。

在大家都在给 LLM Agent 装“技能包”：写 PPT、做网页、生成报告……看起来好像 Skill 越多，Agent 就越强。
但我们做完 OpenSkillEval 后发现：没这么简单。
我们评测的不只是“某个 Skill 有没有用”，而是更完整地看：
不同 Agent / CLI 框架表现如何？Skill 是否真的被读取、遵循并带来收益？最终效果和成本是否值得？
我们总结了 3 个核心发现：
1️⃣ Skill 放在那里，不代表 Agent 会用  (图3)
Skill 明明提供给了 Agent，但它可能根本不读、不调用。即使明确要求使用某个 Skill，也不一定会严格按照 workflow 执行。所以我们不仅看最终结果，也分析 Agent 的执行轨迹。
2️⃣ Skill 不一定提升性能  (图4)
多一个 Skill 不一定更好。有些 Skill 能提升结果，有些会增加步骤和成本，甚至拖累表现。
Skill availability ≠ Skill usage ≠ Performance gain
3️⃣ 好的 Skill 不是 prompt，而是经验包
有价值的 Skill 通常不只是几句 instruction，而是包含清晰适用场景、模板/参考资产/设计先验，并能指导 Agent 但不把输出完全锁死。好的模板和设计先验，往往能显著提高产物质量下限。
