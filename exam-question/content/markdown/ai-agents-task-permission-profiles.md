# 权限策略如何按任务复用

ID: task-permission-profiles
Library: ai-agents
Version: 2026-10-24.1

模块：系统设计 · 难度：L3

## 题干

Agent 需要读写文件、访问网络和后台执行，如何将权限从粗略开关变成可复用的任务策略？

## 参考答案

1. 权限分解：分别定义文件读写网络和本地接口等资源边界；按任务需要授予最小范围的操作能力。

2. 策略组合：明确复用或继承策略时的优先级与拒绝规则；避免宽泛允许无意覆盖保护边界。

3. 实际约束：由执行系统对每次资源访问落实策略；保存策略版本与授权审计并验证越界行为被拒绝。

Thibault Sottiaux 面向高级 Codex 用户介绍了新的 permission profiles。它不是简单地给 Codex 更多权限，而是用可复用、可继承的配置，把文件读写、拒绝规则、网络域名、Unix socket 和管理员 allowlist 拆成更细的边界。

这句话的背景是：
coding agent 正在从一次性对话，变成会读代码、改文件、运行命令、访问网络、甚至在后台持续工作的系统。粗粒度 sandbox 很容易在“安全”和“可用”之间二选一，而 permission profiles 尝试把权限变成按任务配置的策略。

原帖真正重要的不是“Codex 新增了一个权限功能”，而是 AI coding 工具的安全边界正在从开关，变成可复用、可继承、可审计的工作流配置。

那么当 coding agent 能读写文件、访问网络并在后台持续工作，权限边界应该由用户每次临时判断，还是提前写成可复用的任务策略？
