# 插件打包怎样支持可移植

ID: plugin-package-portability
Library: ai-agents
Version: 2026-10-24.1

模块：工具执行 · 难度：L2

## 题干

一个插件同时包含 Skills、MCP 配置和客户端专属扩展，怎样组织才便于跨客户端使用？

## 参考答案

1. 组件声明：使用清单声明插件标识版本及所含能力；把 Skill 资料和 MCP 服务配置作为明确组件组织。

2. 扩展边界：客户端专属功能放在独立命名空间；不能把一个客户端的扩展支持假定为所有客户端都支持。

3. 安装验证：分别验证兼容客户端能发现并加载所需组件；客户端仍需独立执行权限配置及安全检查。

AI插件“大一统”时代来了！Agent Plugins 1.0发布，亚马逊、微软、OpenAI、Cursor联手定标准🔌🤝

各家AI Agent各玩各的插件格式，开发者疲于适配的日子，终于要结束了！🚀

Agent Plugins 刚刚发布了 1.0.0正式版规范——一个由亚马逊、Cursor、微软、OpenAI、Vercel等核心维护者共同制定的开放、厂商中立的插件打包标准。

💡 它解决了什么“千古难题”？

· 过去，为一个AI客户端（比如Cline）写的插件，想在另一个（比如Claude Code）上跑，必须重新打包适配。
· 现在，只需按一套规范打包一次，所有兼容的Agent就能一致地发现和加载它。

📦 核心结构超简单：
一个标准的Agent Plugin就是一个目录，包含必要的清单和可选组件：

```
my-plugin/
├── plugin.json          # 插件标识与版本声明
├── skills/              # Agent Skills（遵循Agent Skills规范）
│   └── summarize/
│       ├── SKILL.md
│       ├── scripts/
│       └── references/
├── mcp.json             # 描述MCP服务器（stdio/HTTP+SSE等）
└── com.example.client/  # 客户端扩展命名空间（特定功能扩展）
```
