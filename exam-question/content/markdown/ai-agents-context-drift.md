# 会话跑偏如何治理

## 题干

长会话中 Agent 开始反复引用旧错误和过期状态，你会如何清理上下文并保留可追溯性？

## 参考答案

1. 污染识别：识别错误结论和过期状态；识别无关内容及重复内容的干扰。

2. 分层清理：按窗口保留近期状态并按需加载长期事实；切换任务时重置历史并携带必要事实摘要。

3. 纠错追溯：对旧错误显式记录更正而非继续引用；清理前归档原始历史以便回查。

Agent用着用着开始答非所问，不是模型笨，是历史里堆了太多噪音把它带偏了。
污染就四类：无关闲聊占token、错误结论被反复引用、过期状态没清掉、重复内容刷屏。
清理打法三种，从轻到重。
轻的是滑动窗口，只留最近几轮，最旧的自动滚出。
换任务时主动重置，清空历史，只带一份关键事实摘要进新会话，这是最容易被忽略的一步。
长期场景用分层隔离，事实存记忆库、状态留窗口，互不污染按需注入。
有个坑要提醒：发现模型说错了要显式写入此结论已更正，不然它后面一直引用那个错答案。
清理前的历史落盘存档，可回查，别清完就找不回了。
一句话：事实外置，噪音清理，历史可回查。
