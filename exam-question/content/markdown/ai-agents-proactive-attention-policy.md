# 主动 Agent 何时应该提醒

ID: proactive-attention-policy
Library: ai-agents

## 题干

监控型 Agent 发现很多变化，如何决定静默记录、汇总提醒、立即打断或请求用户决策？

## 参考答案

1. 提醒价值：综合重要性紧急度可行动性与可信度判断价值；把提醒收益与时机频率及误报成本比较。

2. 分级呈现：低价值信息忽略或记录而非逐条通知；重要不紧急的汇总而重要紧急的及时提醒。

3. 行动权限：已授权且低风险可逆的动作可按规则执行；高风险不确定或不可逆的决定应交由用户确认。

Agent 最大的能力，可能不是“主动找你”，而是知道什么时候不该打扰你。

Reactive Agent 的逻辑很简单：
你问 → 它答。
但 Proactive Agent 不一样。

它需要自己：
观察变化
→ 判断重要性
→ 评估是否值得打扰
→ 决定行动

所以真正的问题不是：
“Agent 能不能主动？”
而是：
“这件事值得占用我的注意力吗？”
我会用一个很简单的公式判断：
Expected Value > Interruption Cost

只有当一条信息的：
重要性 × 紧急度 × 可行动性 × 置信度
大于它带来的：
打扰频率 × 时机 × 认知负担 × 误报成本
Agent 才应该主动出现。

所以主动程度至少应该有 5 级：

Ignore：没价值，不说
Record：记下来，不打扰
Digest：重要但不紧急，汇总说
Notify：值得关注
Interrupt：重要且紧急，立即打断

还有一个我特别喜欢的模型：

Do / Tell / Ask

低风险、高置信度、可逆的事：

Do——直接替我做。

重要但不紧急：

Tell——告诉我。

高风险、低置信度、不可逆：

Ask——回来找我决策。

真正优秀的 Agent，不应该每天发 30 条通知证明自己“很努力”。

理想状态反而是：

它监控了 1000 个 Signal，
处理了 100 个变化，
自动解决了 20 个问题，

最后只找你 2 次。

而这两次你都觉得：

“幸亏它提醒我。”

这才是真正的 Proactive Agent。

一句话总结：

Reactive Agent 的能力，是回答你的问题；Proactive Agent 的能力，是判断什么值得成为你的问题。
