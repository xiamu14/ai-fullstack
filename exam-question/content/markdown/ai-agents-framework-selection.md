## 题干

业务团队问哪个 Agent 框架最强，你会怎样把问题转成可验证的选型决策？

## 参考答案

1. 需求分类：先明确产品入口工作流或多 Agent 等任务形态；列出业务必须具备的工具与运行能力。

2. 工程约束：比较部署成本与现有系统集成难度；检查状态恢复权限和可观测性等运行要求。

3. 任务验证：用代表性真实任务对候选进行对照；根据质量延迟与维护成本取舍而非只看热度。

最近把 GitHub 上热度最高的一批 Agent 框架重新梳理了一遍，发现一个很明显的变化：
Agent 框架已经不再只是“谁更火”的问题，而是在分成几条完全不同的路线。

有的框架更适合做开发者工作流，比如 LangGraph、Dify、LangChain；
有的更像用户入口，比如 Browser-use；
有的在往多智能体协作、任务编排、专业化 Agent 方向走，比如 AutoGen、CrewAI、RAGFlow、Swarm 等。

所以选框架时，最好不要先问“哪个最强”，而是先问：
你到底要解决什么问题？
是做产品入口？ 是做开发工作流？ 是做多 Agent 协作？ 还是做垂直领域的专业 Agent？
