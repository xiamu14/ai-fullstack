# 规划质量如何衡量

ID: planner-execution-gain
Library: ai-agents
Version: 2026-10-24.1

## 题干

两个 Planner 都能生成看似完整的计划，怎样判断哪一个真正帮助了执行器？

## 参考答案

1. 执行对照：对相同任务和执行器比较有计划与无计划表现；固定工具环境等条件以减少混杂因素。

2. 实际增益：关注任务成功率是否提升；同时检查交互步数和执行成本是否合理。

3. 跨条件验证：剔除无帮助或导致退化的计划；在不同任务或执行能力下检查计划的适用范围。

🏃🏻‍♀️ [ 摘要 ] 🏃🏻‍♀️
这篇论文关注长程 LLM Agent 在复杂交互任务中的一个核心短板：执行器往往只能边做边想，缺少稳定的全局规划能力，因此容易出现 planning hallucination 和无效试错。
为了解决这个问题，作者提出 EAGLET，一个面向 long-horizon agent task 的显式 global planner 训练框架。其关键思路不是继续把所有能力都塞进 executor，而是单独训练一个可插拔 planner，为 executor 提供高层计划。方法上，论文先利用强推理模型根据任务指令与成功轨迹自动合成 thinking process 和 global plan，再通过 homologous consensus filtering（HCF）用不同能力层级的同源 executor 做带 / 不带 plan 对照，过滤掉无帮助甚至有害的计划，完成冷启动 SFT。随后，作者设计 executor capability gain reward（ECGR），把 planner 的 RL 目标从“任务是否完成”改成“计划是否让 executor 相比 baseline 更强、且更少步数完成任务”，并结合格式奖励用 GRPO 继续优化 planner。
实验在 ScienceWorld、ALFWorld、WebShop 上表明，EAGLET 能稳定提升不同 executor（包括 GPT-4.1、GPT-5、GiGPO、Llama、Qwen）的表现，同时减少交互步数，并以更低 RL 迭代成本取得优于基线的方法效果。论文最有价值的地方，在于把 planner 质量统一定义为 execution gain，而不是文本表面的“像不像计划”。
