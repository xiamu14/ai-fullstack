# 任务事实源如何保持唯一

ID: single-source-task-state
Library: ai-agents
Version: 2026-10-24.1

模块：上下文记忆 · 难度：L2

## 题干

同一个项目同时有 plan.md、看板和界面状态，怎样避免 Agent 维护出互相矛盾的进度？

## 参考答案

1. 权威来源：为任务进展指定一个明确的权威记录；其他展示应从该来源派生而不是各自编辑独立副本。

2. 写入治理：明确谁能修改以及哪些变更需要确认；保留变更历史以追查错误并支持回滚。

3. 对外展示：只在授权范围内对外提供必要的脱敏视图；核对展示与权威记录的一致性而非制造第二套事实。

最开始，我只是受够了每次对话都要重新给 AI 补课。“我是谁”“我在做什么”“我要 AI 怎么配合我”…

所有的项目进展散在钉钉飞书聊天、会议、文档和脑中的判断里。隔几天没同步，它就落后于真实工作。于是我边用边搭了 VibeWorking：一套本地优先的个人工作系统。

最底层只有三个文件：
- `README.md` 说清系统是什么、先读哪里；
- `AGENTS.md` 约定 AI 怎么协作、什么不能做；
- `CONVENTIONS.md` 规定信息写到哪里、何时确认、如何收尾。

这是一套完整的 Harness 框架，做到后面才发现[汗颜R]

项目 `plan.md` 是事实源，Daily 和 Weekly 负责连续记忆，Git 保存每次变化。AI 可以理解、提议和整理，但关键写回都要经过我确认。完整资料始终留在本机，云端只展示脱敏快照。

边做边用，边用边改，中间也走过弯路。我做过任务看板，后来发现它制造了第二套任务事实，就主动放弃；我也试过让界面承担更多能力，最后把它收回成只读观察台。做得越快，规则、反馈和验证越要跟上。

到八月底，这个系统已经积累了 560 份 Markdown 文档、696 次 Git 提交、1.22M 中文字符，以及 1.72B Token 处理量。数字只是它持续被使用的痕迹。对我更重要的是，AI 终于能接着上一次的工作继续聊。
