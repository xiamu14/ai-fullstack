## 题干

一个 Agent 的 Token 账单突然上涨，你会怎样定位来源并评估降本效果？

## 参考答案

1. 成本拆分：按任务或工作流记录模型调用与用量；区分输入输出及缓存等计费组成。

2. 异常定位：把成本与调用链和任务结果关联；识别重复调用或上下文增长等异常环节。

3. 质量约束：在可比任务上比较优化前后的实际费用；同时检查质量和延迟避免仅追求 Token 下降。

一、解题的关键逻辑
➡️ 第一步：建立Token成本的全链路可见性——先搞清楚钱花在哪：按模型、按功能模块、按用户分层、按会话环节（系统提示/检索上下文/输入/输出）拆分Token用量，看不见成本就管不住成本，模糊的总成本数字没有任何管理意义
➡️ 第二步：区分"好Token"与"坏Token"——不是所有Token消耗都等价，带来任务完成和付费转化的是好Token，无效重试、上下文冗余、恶意刷量产生的是坏Token，成本优化不是一刀切降消耗，而是消灭坏Token、保护好Token
➡️ 第三步：设计多级预警体系——从单会话异常、单用户异常、日/周预算偏离到毛利率红线，设置阈值和告警通道，让成本失控在小时级被发现而不是月底看账单才震惊
➡️ 第四步：建立成本与体验的平衡决策框架——降本动作（换小模型、截断上下文、加缓存）都可能伤体验，每个降本动作都必须配对质量指标做A/B验证，用任务完成率和满意度兜底
➡️ 第五步：把成本意识嵌入产品设计——通过上下文缓存、模型路由、Prompt精简、用量配额等机制，让成本控制成为产品架构的一部分而非事后堵漏
