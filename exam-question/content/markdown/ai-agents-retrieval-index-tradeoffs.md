## 题干

更换向量索引后查询变快但回答变差，你会如何评价索引和分块配置？

## 参考答案

1. 质量测量：用带相关证据标签的业务问题测量召回率；检查漏召回是否导致下游回答质量下降。

2. 资源测量：在代表性数据规模下测量延迟与内存占用；把索引构建及数据更新的成本一起记录。

3. 可比调优：固定 Embedding 与测试条件对比索引参数；联合检查分块粒度与检索配置而非只追求最快查询。

纯新手搞Agent开发，最容易栽在两个坑里：一上来就啃源码，被各种抽象概念直接劝退；或者光学理论不动手，代码一行写不出来。下面这条路线我一步步踩过，每一步都落在实处。
一、先把模型调通，消除陌生感
语言选Python，重点搞熟异步编程和Pydantic数据校验，后面写Agent循环和工具调用时，这两个东西高频出现。弄个LLM的API Key，DeepSeek或智谱都行，用几十行代码跑通一次对话，把请求体长什么样、响应结构怎么拆、Token消耗在哪看清楚。别小看这一步，很多人就是卡在第一次调API上，跑通一次心里就有底了。
二、啃下RAG全链路，这是真工程
RAG不是个概念，是实打实的链路：文档切成块、Embedding向量化、存进向量库、用户提问时检索相似块、拼进Prompt喂给LLM。注意，Embedding模型和生成模型是两个不同的API，别搞混。先用Chroma在本地把流程跑通，再上Milvus或Qdrant，亲手感受一下HNSW和IVF这类索引在延迟和召回上的取舍。我当初在这一步被检索慢的问题折腾得够呛，调了索引类型和分块大小才把延迟压下去。
三、拆开Agent的本质，手写一次循环
Agent说白了就是Chatbot加Tools加Loop。LLM推理后判断要不要调工具，要就执行并拿回结果，塞进上下文再推理，直到输出最终答案。先别碰LangChain，用纯Python手写一个ReAct循环，把“思考-行动-观察”每一步打出来，debug时清楚每一步的输入输出。我当初写了不到50行，跑通后那种豁然开朗的感觉，比看十篇教程都管用。
四、工具调用和记忆，拉开差距的细节
Tool是本地函数调用，MCP是远程调用协议，让工具能即插即用。Skill可以渐进式加载，避免一次性塞太多Token。工具不用花哨，bash、文件读写、搜索、编辑器就够用。短期记忆直接靠上下文窗口，长期记忆得靠摘要压缩存向量库，阈值和过期策略就是工程细节。至于Multi-Agent，大部分场景单Agent加两三个工具绰绰有余，别被多智能体带偏了节奏。
五、找一个实战项目，边看边改
拿XingClaw这类开源项目开刀，按顺序啃：总览文档搞懂架构，AI层看LLM接口怎么封装的，核心Agent Loop死磕每一行，内置工具实现研究透，最后看IM层怎么对接飞书。边看边改，把工具换成自己的业务接口，加重试和异常兜底，跑通一个能干活的东西，你就算真正入门了。我那时接了个周报生成Agent，每天定时拉飞书数据调模型写摘要，再推到群里，跑起来那一刻就知道，这玩意儿真能落地。#大模型应用[话题]# #agent[话题]# #人工智能[话题]# #AI应用开发[话题]# #大模型[话题]#

【开源】做 RAG、Agent Memory 不一定要上 Milvus、Elasticsearch 这类独立服务了：Zvec 直接嵌进应用，一个进程就能完成向量 + 全文 + 混合检索。

alibaba/zvec 是阿里开源的 In-Process Vector Database，最大的特点就是轻：不用启动数据库服务器，也不用复杂配置，直接作为库嵌入 Python、Go、Rust 等应用。 ￼

它不只是向量检索，还把 Dense Vector + Sparse Vector + Full-Text Search + Structured Filter 放到了一起，可以直接做 Hybrid Search；同时支持 HNSW、DiskANN 等索引，以及 WAL 持久化。 ￼

现在更有意思的是它开始明显面向 AI Agent：最新版本增加 zvec-grep（zg），把 ripgrep、BM25 和向量搜索统一成一个本地搜索 CLI；同时支持 ReMe 作为 Agent Memory 的存储后端。 ￼

一句话：传统向量数据库解决“怎么存向量”，Zvec 更像是在做 AI 应用里的本地搜索基础设施。

适合 RAG、Agent Memory、AI Coding、语义搜索、本地 AI、Hybrid Search。
